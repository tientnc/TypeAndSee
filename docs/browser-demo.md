# Browser demo

The public GitHub Pages demo uses CLIP embeddings and Orama vector search entirely in the visitor's browser. GitHub serves static files. No server inference, metered model API, or cloud database is used by this deployment.

The sample collection includes five attributed photographs and precomputed image embeddings. The first query downloads the quantized CLIP text encoder from Hugging Face. Adding photos also downloads the vision encoder. Model files can be cached by the browser, and initial loading can be slow on a limited connection.

Photos added by a visitor are resized to a browser copy. These copies and their 512-dimensional embeddings are stored in IndexedDB on that device. Orama rebuilds its vector index from those saved records after a reload. Added photos are not shared with other visitors. Clearing site data removes the local library and cached models.

The browser demo is semantic retrieval. It does not implement generated explanations, server authentication, shared cloud uploads, or an agent workflow. The Python API retains the separate optional explanation and cloud-storage components.

## Run locally

```bash
python3 -m http.server 8000 --directory web/images
```

Open `http://localhost:8000`. A modern desktop browser is recommended. JavaScript, WebAssembly, workers, IndexedDB, and access to jsDelivr and Hugging Face are required. An HTTPS origin or localhost is needed for file hashing.

## Verify

With Chrome or Chromium installed, run:

```bash
uv sync --extra test
uv run python scripts/browser_smoke.py
```

This runs real CLIP inference and checks sample-query ranking, photo import, duplicate detection, persistence after a page reload, and resetting the library. It saves a screenshot and JSON report in a temporary directory. Use `--url https://tientnc.github.io/TypeAndSee/web/images/` to check the deployed image site, or `--seed` locally to regenerate the bundled sample embeddings after changing the sample collection.

## Publish

Use the public repository's GitHub Pages configuration with the publishing source set to branch `main`, folder `/`. The root page redirects to the movie app at `web/`; the image app is at `web/images/`. The `.nojekyll` file keeps publication static. This deployment does not use paid Actions runners, Git LFS, a custom paid domain, or paid hosting upgrades.

GitHub Pages has service and usage limits. The app can become unavailable if those limits or the external asset providers' limits are reached. No paid upgrade is configured by this repository.

Sample-image source links, authors, licenses, and resizing notices are listed in the app's credits page and `web/images/demo/sources.json`. Sample embeddings were generated by the same pinned browser model used for queries; the Python app uses a separate OpenCLIP model and its index is not interchangeable.
